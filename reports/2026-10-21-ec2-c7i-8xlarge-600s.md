# EC2 c7i.8xlarge benchmark, 2026-10-21

This run compares PostgreSQL master with two steps of the
pg_stat_statements patch series:

- `customstats`: [`c0f1ee3f8fb4`](https://github.com/samimseih/postgres/commit/c0f1ee3f8fb46b6c370251201e9d8cf3f030fe4b), custom pgstat entries while query text still uses the external file.
- `customstats + DSA query text`: [`1d8654a01fcc`](https://github.com/samimseih/postgres/commit/1d8654a01fcca998adff5f318b52d6b8ee3e3214), custom pgstat entries plus DSA-backed query text.
- Baseline: [`6b9f40d49ae3`](https://github.com/postgres/postgres/commit/6b9f40d49ae3), PostgreSQL master.

Both comparisons ran on EC2 `c7i.8xlarge` with release/perf builds, no
assertions, `pg_stat_statements.max=5000`, clients `1 2 4 8 16 32 64 128
256`, and 600 seconds per point.  Each patch was compared with the upstream
run from the same EC2 benchmark run, so the upstream columns below are paired
with that patch run.

Detailed generated reports:

- [customstats](2026-10-21-ec2-c7i-8xlarge-customstats-600s.md)
- [customstats + DSA query text](2026-10-21-ec2-c7i-8xlarge-customstats-dsa-query-text-600s.md)

## Summary

The churn workload is the interesting case.  `customstats` improves
`hotcold_100m` by up to `+96.8%`, and `customstats + DSA query text` improves
it by up to `+104.4%`.  `select_only` stays roughly flat; the largest dip is
at 128 clients, `-6.1%` for `customstats` and `-3.0%` for `customstats + DSA
query text`.

Both patch runs retained all 4000 popular statements at every churn sample.
The `customstats + DSA query text` run kept query-text memory bounded: sampled
`qtext_count` high-water was `5523`, sampled query-text payload high-water was
`447 KiB`, and sampled query-text DSA size was `1.00 MiB` during churn.

The wait-event samples show the main win directly: upstream spends many
samples waiting on the old `pg_stat_statements` LWLock during churn, while both
patch runs reduce that to zero.  The replacement pgstat/query-text waits are
much smaller than the removed bottleneck.

## Retention And Memory

Retention and memory values are sampled every 5 seconds during each point.
Detailed min/avg/max values are in the generated reports linked above.

| comparison | popular retention | entry high-water | qtext count high-water | qtext payload high-water | qtext DSA high-water |
| --- | ---: | ---: | ---: | ---: | ---: |
| customstats | 4000/4000 at every churn sample | 43.2 MiB entry DSA | 0 | 0 B | 0 B |
| customstats + DSA query text | 4000/4000 at every churn sample | 43.2 MiB entry DSA | 5,523 | 447 KiB | 1.00 MiB during churn |

The zero query-text DSA values in the `customstats` row are expected, because
that patch still uses the external query-text file.  The DSA query-text run
uses `pg_stat_statements.max` as the main admission target for this workload;
the query-text byte cap did not become the limiting factor.
